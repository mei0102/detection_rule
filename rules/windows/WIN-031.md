# WIN-031 Defender除外指定とWeb取得・動的実行が同じPowerShellに同居

**検知概要：** 同じPowerShell記録に、Defenderの除外を追加・設定する指定と、Web取得・文字列の動的実行が揃うケースを探す。

**検知意図：** 保護全体を停止せず、除外設定を使って取得コードを動かそうとする処理を調べる。除外の適用成功は別途確認する。

**過検知予想：** 正規インストーラや管理スクリプトが、除外設定と取得・実行をまとめて行う場合。

|判断の目安|内容|
|---|---|
|**重要度**|**P2：通常調査**（感染確定ではない）|
|重要度の理由|除外指定と取得・評価が同居するが、4104本文だけでは分岐の実行や設定成功を確定できない。|
|ルールの役割|WIN-018に防御変更の文脈を追加する詳細化ルール。独立した侵害証拠として二重加点しない。|
|発報したら|除外の実設定、取得先、スクリプト全体、作業承認を確認。|
|疑いを強める追加証拠|未承認の除外が反映され、取得したコードの不正な後続処理が裏付けられればP1へ引上げ。|
|検知価値の評価|中（設計上）。単独の除外操作より対象を絞るが実測の精度は不明。|

PowerShell Script Block Loggingの4104と本文収集が必須。実環境の取得状況は不明。最新週の探索から除外条件の見落としを確認し、基礎となる既刊の情報を採用したもので、新規キャンペーンの発見ではない。

## 汎化

- 脅威固有の指標：攻撃者IP・ファイル名は使わない。MpPreferenceと取得・評価関数に依存。
- 共通する実装パターン：保護対象を減らす設定と遠隔コードの取得・評価を一つの処理に含める。
- 長期利用できる攻撃行動：防御の除外設定を悪用した実行準備。
- 今回採用する条件と理由：除外設定、対象パラメータ、HTTP URL、取得、動的評価を同一断片で要求して、通常の除外変更だけから絞る。
- 採用しない条件と理由：除外対象の実パス・取得物との一致は静的な本文一致では判定しない。未提供の資産台帳も前提にしない。

## 検知意図と限界

- 検知できること：対象の文字列・関数が同じ4104断片に含まれること。
- 検知できないこと：処理順、値と関数の依存関係、除外の適用、ダウンロード成功。コメントや未実行の関数定義でも一致し得る。
- 意図的に検知しないこと：分割断片、別スクリプト、レジストリ/API経由の設定、ASR/CFA専用除外、Invoke-Expression以外の実行。
- 想定される回避方法：関数名や引数の動的生成、別プロセスへの分離、除外を事前に設定する。

## 誤検知

- 主な正常動作：正規ソフト配布、開発環境のセットアップ、管理ジョブ。
- 誤検知を識別する追加情報：配布ジョブ、実行者、スクリプト署名・内容、設定履歴、取得物。
- 改善方法：承認済み処理の内容と実際の変更を照合し、成功・失敗や未実行箇所を分ける。
- 除外が必要な場合の対象と根拠：承認済み主体・スクリプト内容・作業時間の組のみ候補。SPLには除外なし。
- 改善により新たに生じる検知漏れ：承認済みスクリプトの改変や、追加情報が欠落した攻撃。

## SPL

- 現行SPL：該当なし（2026-09-13追加）。WIN-018の強い文脈を区別する詳細化。
- 提案SPL：

```spl
index=detection_lab log_type="windows" channel="Microsoft-Windows-PowerShell/Operational" event_id=4104 earliest=-10m@m latest=-5m@m
| where match(ScriptBlockText,"(?i)\\b(Add|Set)-MpPreference\\b")
    AND match(ScriptBlockText,"(?i)(^|\\s)-Exclusion(Path|Process|Extension)(\\s|:)")
    AND match(ScriptBlockText,"(?i)https?://")
    AND match(ScriptBlockText,"(?i)(DownloadString|Invoke-WebRequest|Invoke-RestMethod|\\biwr\\b|\\birm\\b)")
    AND match(ScriptBlockText,"(?i)(\\bInvoke-Expression\\b|\\biex\\b)")
| stats count as matching_fragments
        min(_time) as first_seen
        max(_time) as last_seen
    by host ScriptBlockId
| eval rule_id="WIN-031", attack_id="T1685",
       risk_object=host, risk_object_type="system", risk_score=40, severity="medium"
```

- 差分：ESCUのプロセス引数による除外指定の考え方を4104へ移し、取得と評価の同居を追加。元SPLのコピーやCIM移植ではない。
- index、sourcetype、製品固有フィールドの置換箇所：index/log_typeは仮置き。host/channel/event_idはComputer/Channel/EventID、ScriptBlockId/Textは4104 XML項目へ対応。実sourcetypeを確認して限定する。
- 想定負荷：中（本文への複数正規表現。未測定）。
- 負荷を抑える工夫：チャネル・4104・短時間窓で先に限定。join/transaction/全件ソートなし。CIMマクロやlookupは不使用。

## Splunk ES設定案

- 実行間隔：5分。
- earliest/latest：-10m@m / -5m@m。
- trigger：結果行数 > 0。同じhost・ScriptBlockIdのWIN-018と一件の調査にまとめる。
- suppression/throttling：初期は無効。同一断片の重複を確認後、host・ScriptBlockIdで5分抑制する案。両ルールの単純なRisk加算は避ける。
- severity：medium（P2）。
- risk score：40（未検証）。RBA採用時はWIN-018を置換・統合する設計が必要で、列の出力だけでは加算されない。
- risk object／type：host / system。
- security domain：endpoint。
- notable title：WIN-031 Defender除外指定とWeb取得・動的実行が同居。
- drilldown：host・ScriptBlockIdで本文を取り直し、設定変更の記録・承認ジョブ・後続プロセスを照合。

## 閾値

- 初期値：同じ断片に全条件が1件以上一致。
- 根拠：件数ではなく処理の組み合わせを使う設計。実測値ではない。
- 高感度設定：除外指定だけを別の低優先度調査サーチへ分ける案。
- 標準設定：提案SPL。
- 低誤検知設定：実設定への反映と未承認の取得物を追加確認する案。追加ログの取得が前提。
- ベースライン取得方法：30日の一致を管理ジョブ・実行主体で分類し、WIN-018との重複と正規処理の内容を確認。

## 人が評価すべき点

- 採用判断に必要な確認事項：4104本文の欠落・分割、正常配布の該当、設定反映を確認できるログ。
- 不足データ：実ログ、TP/FP、ジョブ台帳、ES設定、実行時間。
- 最大のリスク：静的な同居を成功した防御回避と誤認すること、WIN-018との二重通知・二重加点。
- 推奨判断：実装候補（WIN-018の調査内容を具体化する用途）。
- 推奨理由：既存の保護停止監視で見えない除外指定を、遠隔コード実行の文脈と一緒に評価できる。
