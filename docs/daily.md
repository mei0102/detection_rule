# 日次追加

毎日1件以上を目標に、ATT&CKマトリクスの空欄と対象ログの利用可能性を照合して選びます。
同じ挙動の名前替えやIOCだけの更新は新しいTTPカバレッジとして数えません。

1. 最新mainと日付を確認。当日追加済みなら重複追加を避ける。
2. ATT&CK、SigmaHQ、ESCU、製品公式ログ仕様から観測根拠を調査。参照したURL、版、ライセンスを記録。
3. 必須項目、検知式、5分窓・集約キー・閾値、誤検知、検知できない条件、調査手順を揃える。
4. 独自JSONと正例・負例を追加。相関ルールは閾値直下・窓外・グループ分離も検証。
5. buildと全テストを実行し、生成物の差分を確認。新規ルールはexperimental。
6. 通常pushで公開し、コミットと件数を報告。保護ブランチでは作業ブランチをpushして状況を知らせる。force pushをしない。

次の候補：Windows 4104のスクリプト内容、4740との相関、4728の特権グループ追加、NDRのSMB横断接続、Proxyの大容量アップロード。
十分な根拠やテストを用意できない日は無理に追加せず、阻害理由を報告して次回に続けます。
日次実行はCodexのこのタスクのスケジュールで管理します。GitHub Actionsは検証のみで、AI生成や日次追加は行いません。
