# WIN-025 WinRM配下で転送ツールを起動

**検知概要：** WinRMの処理から、URL付きのCertUtil・BITSAdmin・MSHTAが起動する動きを探す。

**検知意図：** リモート管理接続を使った攻撃用ファイルの取得・実行準備を調べる。

**過検知予想：** 正規リモート配布。 悪性かどうかは、利用目的や実行主体の確認が必要。

|重要度の理由|不審な操作・条件を絞っているが、正規リモート配布でも成立し、追加確認が必要。|

4688の親プロセス名・コマンドラインを収集。

## 汎化

- 脅威固有の指標：wsmprovhost親、certutil/bitsadmin/mshta、URL。
- 共通する実装パターン：リモート管理セッションから取得ツールを起動。
- 長期利用できる攻撃行動：WinRM配下で転送ツールを起動。特定攻撃者への帰属は行わない。
- 今回採用する条件と理由：wsmprovhostを親に、CertUtil／BITSAdmin／MSHTAがHTTP(S)を指定して起動。 この観測範囲でリモート管理セッションから取得ツールを起動の候補を抽出するため。
- 採用しない条件と理由：他の子プロセス、親情報のないイベントは今回の条件外。別の観測・検知条件が必要なため、この検索に混在させない。未提供の資産台帳による除外も行わない。

## 検知意図と限界

- 検知できること：wsmprovhostを親に、CertUtil／BITSAdmin／MSHTAがHTTP(S)を指定して起動。
- 検知できないこと：正規のリモート配布も一致。親名のない4688では検知できない。
- 意図的に検知しないこと：他の子プロセス、親情報のないイベント。
- 想定される回避方法：上記の条件外の経路・表記・タイミングへ変更する、または必要ログの記録を妨げる。

## 誤検知

- 主な正常動作：正規リモート配布。
- 誤検知を識別する追加情報：WinRMセッションの利用者・接続元、URL、保存先。
- 改善方法：WinRM認証と取得結果を照合。追加情報が取得できる場合の案で、今回のSPLには未適用。
- 除外が必要な場合の対象と根拠：正規リモート配布のうち、上記情報と承認記録で一致を確認した主体・対象・時間帯だけ。現時点の除外はなし。
- 改善により新たに生じる検知漏れ：承認済み主体の侵害を除外する恐れ。追加条件を必須にすると、正常判別用の証拠が欠落した攻撃も見逃す。

## SPL

- 現行SPL：変更前のリポジトリ版（`5d42ac6`）。顧客環境の稼働版ではない。

<details>
<summary>現行SPLを表示</summary>

```spl
index=detection_lab log_type="windows" earliest=-10m@m latest=-5m@m
| where channel="Security" AND event_id=4688
    AND match(ParentProcessName, "(?i)(^|[\\\\/])wsmprovhost\\.exe$")
    AND match(process_path, "(?i)(^|[\\\\/])(certutil|bitsadmin|mshta)\\.exe$")
    AND match(command_line, "(?i)https?://")
| stats count as observed
        min(_time) as first_seen
        max(_time) as last_seen
        values(process_path) as tools values(command_line) as commands
    by host
| eval rule_id="WIN-025", attack_id="T1021.006"
```

</details>

- 提案SPL：検知条件を維持し、ES設定用の出力列を追加。

```spl
index=detection_lab log_type="windows" earliest=-10m@m latest=-5m@m
| where channel="Security" AND event_id=4688
    AND match(ParentProcessName, "(?i)(^|[\\\\/])wsmprovhost\\.exe$")
    AND match(process_path, "(?i)(^|[\\\\/])(certutil|bitsadmin|mshta)\\.exe$")
    AND match(command_line, "(?i)https?://")
| stats count as observed
        min(_time) as first_seen
        max(_time) as last_seen
        values(process_path) as tools values(command_line) as commands
    by host
| eval rule_id="WIN-025", attack_id="T1021.006"
| eval risk_object=host, risk_object_type="system",
       risk_score=40, severity="medium"
```

- 差分：末尾に`risk_object`、`risk_object_type`、`risk_score`、`severity`を追加。検知件数を変える条件変更はなし。列の追加だけではRiskイベント・Notableは生成されない。
- index、sourcetype、製品固有フィールドの置換箇所：`index=detection_lab`は仮置き。実indexと確認済みsourcetypeへ置換し、`log_type`は共通分類を用意するか実ログ条件へ置換。event_id←EventID、channel←Channel、host←Computer。小文字の共通列とXML原文列の対応は各収集方式で要確認。必要列：`_time`, `log_type`, `channel`, `event_id`, `host`, `ParentProcessName`, `process_path`, `command_line`。
- 想定負荷：低（固定時間窓で条件抽出と単段集約を行うため。データ量・同時実行数による概算で未測定）。
- 負荷を抑える工夫：必要列・対象ログ・時間窓を先に限定し、集約後の少数行で追加計算。CIM対応と加速済みData Modelが確認できる場合のみtstats化を検討。未提供のData Modelは前提にしない。

## Splunk ES設定案

- 実行間隔：5分（設定案）。
- earliest/latest：`-10m@m` / `-5m@m`。取り込み遅延5分を仮定。
- trigger：結果行数 > 0、各結果行を対象。評価後にRisk Analysis等の応答アクションを別途設定。自動のNotable生成は未設定。
- suppression/throttling：初期は無効。重複実績を確認後、同じrule_id・risk_objectの反復を検索窓相当で抑制する案。別対象・別段階まで抑える可能性があるため宛先等の追加キーを評価。
- severity：`medium`（P2の調査優先度に対応。悪性確定ではない）。
- risk score：`40`（未検証の相対値）。Risk Analysisアクションは別途設定。スコアだけで重要度を判断しない。
- risk object／type：`host` → `risk_object` / `system`。出力に残る主体を使用し、資産・ID正規化と共有IPを確認。
- security domain：`endpoint`。
- notable title：`WIN-025 WinRM配下で転送ツールを起動`。Notable化を採用する場合の案。
- drilldown：結果の`host`を元ログの同じ列へ渡し、検知対象窓の前後5分を再検索。WinRMセッションの利用者・接続元、URL、保存先を表示・照合。未取得の列は追加収集が必要。

## 閾値

- 初期値：wsmprovhostを親に、CertUtil／BITSAdmin／MSHTAがHTTP(S)を指定して起動。 数値のないイベント・文字列条件は1件一致で結果候補。
- 根拠：上記行動の候補を切り出す設計値。参照ルールの推奨値や実環境の正常分布を証明する値ではない。
- 高感度設定：子プロセス候補を拡張する案。記載以外の条件は標準と同じ。SPLには未適用。
- 標準設定：提案SPLの条件。初期値と同一。
- 低誤検知設定：未承認の接続元と取得成功を要求。追加情報が必要な案は取得確認が前提で、効果は未確認。
- ベースライン取得方法：30日を同じ検索窓・集約主体`host`で区切り、正常と確認した正規リモート配布とそれ以外を分け、件数・対象数・数値条件の分布を比較。存在しない統計は補完しない。

## 人が評価すべき点

- 採用判断に必要な確認事項：Windows監査設定・対象イベントの欠落、XML項目の抽出状況。WinRMセッションの利用者・接続元、URL、保存先で正常業務と識別できるか。
- 不足データ：実index/sourcetype、必要列の充足率、ESバージョン、発報数・TP/FP判定、資産・業務台帳、実行時間。
- 最大のリスク：正規リモート配布との衝突と、他の子プロセス、親情報のないイベントの取りこぼし。
- 推奨判断：実装候補（本番採用の確定ではない）。
- 推奨理由：観測条件を具体化できるため。必須フィールドと正常業務の識別を確認してから採用を判断する。
