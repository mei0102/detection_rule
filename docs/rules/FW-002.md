# FW-002 内部複数ホストへのRDPポート接続許可

- 状態：experimental / 重要度：medium
- SIEM：Splunk Enterprise / Splunk Cloud Platform (SPL)
- 対象ログ：fw

## MITRE ATT&CK Matrix上の位置

|戦術（Matrixの列）|親技法|サブ技法|本ルールとの関係|
|---|---|---|---|
|[TA0008 Lateral Movement](https://attack.mitre.org/tactics/TA0008)|[T1021 Remote Services](https://attack.mitre.org/techniques/T1021)|[T1021.001 Remote Desktop Protocol](https://attack.mitre.org/techniques/T1021/001)|主な検知仮説|

内部の複数宛先3389/TCPへの許可をRDP横移動のハンティング候補とする。RDPの識別・認証を検知式に含まないため、T1021.001への関連は代理指標である。

[リポジトリ全体のマトリクス](../matrix.md)。これは技法の一部に対する検知仮説で、技法全体のカバレッジではありません。

## 対象ログ・必要フィールド

- 検知に必須：`_time`, `action`, `dest_ip`, `dest_port`, `dest_zone`, `log_type`, `src_ip`, `src_zone`, `transport`
- 調査に推奨：`src_ip`, `dest_ip`, `dest_port`, `action`, `src_zone`, `dest_zone`, `session_id`, `bytes_in`, `bytes_out`

内部間通信のFW可視性。internalは組織の資産・ネットワーク定義で付与。

型・元項目・欠損監視は[フィールド定義](../log-sources.md)を参照。推奨項目が未採取の場合は調査結果に制約を記録します。

## 検知条件

`=` は一致、`~=` は正規表現一致、`>=` は以上、`AND` はすべて満たす意味です。`dc()` は異なる値の数です。`~=` は説明・JSON定義の記号で、SPL本文では `match()` に変換します。必須フィールドがNULLなら対象外です。

```text
log_type = "fw"
AND transport = "tcp"
AND dest_port = 3389
AND action = "allow"
AND src_zone = "internal"
AND dest_zone = "internal"

GROUP BY src_ip
WINDOW = 300 seconds
dc(dest_ip) >= 10
```

## 検知SPL（Splunk）

`index=detection_lab` を正規化済みログのindexに変更してください。5分間隔、5分遅延の検索を想定しています。生ログにそのまま適用せず[Splunk導入手順](../deployment.md)でフィールドを確認してください。

```spl
index=detection_lab log_type="fw" earliest=-10m@m latest=-5m@m
| where isnotnull(_time)
    AND isnotnull(action)
    AND isnotnull(dest_ip)
    AND isnotnull(dest_port)
    AND isnotnull(dest_zone)
    AND isnotnull(log_type)
    AND isnotnull(src_ip)
    AND isnotnull(src_zone)
    AND isnotnull(transport)
    AND transport="tcp"
    AND dest_port=3389
    AND action="allow"
    AND src_zone="internal"
    AND dest_zone="internal"
| stats dc(dest_ip) as observed min(_time) as first_seen max(_time) as last_seen by src_ip
| where observed >= 10
| eval rule_id="FW-002", attack_id="T1021.001"
```

## 誤検知とチューニング

踏み台・管理ツール・運用者の一括接続。

## 調査手順・判断基準

1. 送信元ごとの10以上のdest_ip、試行順序、FW action、セッション継続時間と通信量を確認する。allowはポリシー許可でありTCP確立やRDPログオン成功ではない。

2. src_zone/dest_zoneのinternal分類が組織のネットワーク定義に一致するか確認する。送信元が正規踏み台・管理エージェントか、宛先群が承認済みの管理対象かを調べる。

3. NDRのRDP識別、宛先端末の4624 LogonType 10、4625、TerminalServices系の収集ログで実際のRDP利用を確認する。IPとhostは当該時刻の資産情報で結び付ける。

4. 成功セッションがあればユーザー、送信元、初回利用か、管理時間外かを確認し、宛先の4688や新規サービス・タスクを追う。認証失敗だけなら探索・資格情報試行の可能性も残す。

5. 承認外端末への成功ログオンと不審操作があれば影響端末・ユーザー・開始時刻を整理して引き継ぐ。管理作業と一致する場合は送信元単独ではなく対象範囲と期限を含めて例外化する。

### 調査SPL：元イベントの時系列

`REPLACE_...` を検知結果の集約キーに置換します。過去アラートでは `earliest` / `latest` を発生時刻の前後15分の絶対時刻（Unix秒）に変更してください。下記の直近30分は調査開始例です。別ログ種別との照合は対象indexとlog_typeを切り替え、端末IP・host・ユーザーの対応を確認して行います。

```spl
index=detection_lab log_type="fw" src_ip="REPLACE_SRC_IP" earliest=-30m@m latest=now
| sort 0 _time
| table _time host log_type channel event_id src_ip dest_ip dest_port action src_zone dest_zone session_id bytes_in bytes_out _raw
```

推奨フィールドが未抽出なら `_raw` を参照します。調査SPLは検知条件を再適用せず、同じキーの正常・異常両方を表示します。キー以外の宛先・利用者へ展開する場合は該当セレクタを外して範囲を広げます。

## 限界・見逃す条件

- 代理指標：3389はRDP以外でも利用でき、FW allowだけでは横移動を証明できない。成功ログオンやアプリケーション識別との突合が必須。

- 対象外：非標準ポート、RD Gatewayやトンネル、UDPだけの記録、10ホスト未満・低速の移動は検出しない。

- 内部可視性：FWを通らない内部通信や誤ったzone分類は対象外になる。NATされた複数送信元は一つのsrc_ipとして集約される。

- 正規操作：踏み台からの一括保守と形が一致する。既知踏み台でも侵害され得るため、送信元IPの恒久的な全面除外は避ける。

共通制約：固定5分窓をまたぐ閾値未満の分散、5分を超える収集遅延、必須フィールド欠損、重複転送の影響を評価してください。Splunk上の実ログ検証・PCRE評価は未実施で、合成テストの成功は本番検知率を示しません。
