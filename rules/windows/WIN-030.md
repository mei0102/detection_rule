# WIN-030 起動した一時VBScriptをRunキーへ登録

**検知概要：** Temp/AppData内のVBScriptを起動した後、同じ端末・ログオンセッションで、そのパスが15分以内にRun/RunOnceの値へ書き込まれる動きを探す。

**検知意図：** 一時的なスクリプト実行を、ログオン後も起動する仕組みに残す動きを調べる。登録コマンドの文字列ではなく、4657の変更後データを使う。

**過検知予想：** 管理者の初期設定・ログオンスクリプト導入。作業申請とスクリプト内容の照合が必要。

**必須前提：** 4688のCommandLineと、Audit Registry成功監査・対象RunキーのSet Value SACLによる4657が必要。未収集なら実装保留。監査設定を変更する操作は行っていない。

## 汎化

- 脅威固有の指標：固定の値名・ファイル名・C2は使わない。wscript/cscriptとVBScriptの実装には依存。
- 共通する実装パターン：一時領域のコード起動後、同じコードをログオン起動へ登録。
- 長期利用できる攻撃行動：実行したペイロードを端末へ定着させる操作。
- 今回採用する条件と理由：端末・SubjectLogonId・スクリプトパスと順序を一致させ、単独Run変更から絞る。
- 採用しない条件と理由：特定RMMの親名や攻撃者の値名は変更可能。Sysmon/EDR固有のレジストリイベントは前提にしない。

## 検知意図と限界

- 検知できること：対象スクリプトの起動後、同一セッションでそのパスを含むRun/RunOnce値へ変更されたこと。
- 検知できないこと：悪性・次回起動・権限昇格の成立。同じパスのファイル内容が途中で変わったかは不明。変更後文字列内のパスが実際に起動される引数かは別途確認。
- 意図的に検知しないこと：登録が先、別セッション、環境変数・相対パス・短縮名、別言語、Startupフォルダ、RunOnceEx。
- 想定される回避方法：別パスへコピーして登録、遅延、別ログオン主体へ切替、ラッパーや他の永続化方式を使う。

## 誤検知

- 主な正常動作：正規のログオンスクリプトや管理エージェントの導入。
- 誤検知を識別する追加情報：スクリプト実体、変更者、書込プロセス、導入ジョブ、変更申請。
- 改善方法：実体と承認ジョブを照合。AppDataや正規署名だけで除外しない。
- 除外が必要な場合の対象と根拠：申請と実体が一致する主体・値・時間帯のみ候補化。現行の除外なし。
- 改善により新たに生じる検知漏れ：承認済み処理の改変、管理アカウント侵害、追加証拠の欠落。

## SPL

- 現行SPL：該当なし（2026-09-12追加）。
- 提案SPL：

```spl
index=detection_lab log_type="windows" channel="Security" event_id IN (4688,4657) earliest=-25m@m latest=-5m@m
| where (event_id=4688 AND match(NewProcessName,"(?i)(^|[\\\\/])(wscript|cscript)[.]exe$"))
    OR (event_id=4657 AND match(ObjectName,"(?i)^\\\\registry\\\\(machine|user\\\\[^\\\\]+)\\\\software\\\\(wow6432node\\\\)?microsoft\\\\windows\\\\currentversion\\\\run(once)?$"))
| eval script_reference=if(event_id=4688,CommandLine,NewValue)
| rex field=script_reference "(?i)(?:^|\\s)(?:\"(?<quoted_script>[A-Z]:\\\\[^\"]+[.]vbs)\"|(?<bare_script>[A-Z]:\\\\[^\\s\"]+[.]vbs))(?=\\s|$)"
| eval script_path=lower(coalesce(quoted_script,bare_script))
| where match(script_path,"(?i)\\\\(temp|appdata)\\\\")
| sort 0 _time
| streamstats time_window=15m current=f
        max(eval(if(event_id=4688,_time,null()))) as script_started
    by host SubjectLogonId script_path
| where event_id=4657 AND _time > script_started AND _time-script_started <= 900
    AND _time >= relative_time(now(),"-10m@m")
| table _time host SubjectLogonId script_path script_started
        ObjectName ObjectValueName NewValue ProcessName
| eval rule_id="WIN-030", attack_id="T1547.001",
       risk_object=host, risk_object_type="system", risk_score=70, severity="high"
```

- 差分：起動文字列と実際の変更後データからパスを照合。書込プロセスが起動したVBScript自身であるとは主張しない。
- index、sourcetype、製品固有フィールドの置換箇所：index/log_typeは仮置き。event_id/host/channelはEventID/Computer/Channelへ対応。他列はWindows XML項目を抽出。4657のObjectNameはREGISTRY形式、NewValueは変更後文字列。同じログオンID表記へ正規化し実sourcetypeで限定。
- 想定負荷：高（イベント混在の全件ソート・時系列状態保持。未測定）。
- 負荷を抑える工夫：イベントID、キー末尾、スクリプトの場所をソート前に限定。join/transactionなし。streamstatsの状態上限と同時実行数を確認。

## Splunk ES設定案

- 実行間隔：5分。
- earliest/latest：-25m@m / -5m@m。
- trigger：結果行数 > 0。自動隔離や本番反映は未設定。
- suppression/throttling：初期は無効。同じrule_id・host・script_path・ObjectName・ObjectValueNameの反復を確認後に15分抑制する案。別の再登録を隠す可能性がある。
- severity：high（P1の調査優先度）。
- risk score：70（未検証）。別途Risk Analysisアクションが必要。
- risk object／type：host / system。
- security domain：endpoint。
- notable title：WIN-030 起動した一時VBScriptをRunキーへ登録。
- drilldown：同じhost・SubjectLogonIdの4688/4657で前後の操作を確認し、ProcessNameとスクリプト実体を照合。

## 閾値

- 初期値：起動後15分以内に同一パスの変更1件。20分検索し、最終5分の変更を返す。
- 根拠：順序と内容の一致で絞る設計値。報告の正確な段階間隔や環境の正常分布に基づく値ではない。
- 高感度設定：起動前提を外したRun変更を別のP2調査サーチにする案。
- 標準設定：提案SPL。
- 低誤検知設定：未承認の書込主体や次回ログオン実行との相関を追加する案。取得確認が必要。
- ベースライン取得方法：30日を同じ端末・セッション・パスで比較し、承認済み導入処理の一致を確認。

## 人が評価すべき点

- 採用判断に必要な確認事項：4657とSACL、両イベントのログオンID・絶対パス、書込データの収集。
- 不足データ：実ログ、列充足率、TP/FP、監査設定、業務台帳、実行時間。
- 最大のリスク：4657未取得で無検知なのにカバレッジありと誤認すること。
- 推奨判断：実装候補（4657未収集なら追加調査）。
- 推奨理由：既存ルールにないRun登録の実データを起動記録へ結び付け、永続化経路を補う。
